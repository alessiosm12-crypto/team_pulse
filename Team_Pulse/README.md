# Team Pulse Local Prototype

Локальный прототип Team Pulse работает в двух режимах:

- статический режим: `index.html` можно открыть прямо в браузере, данные хранятся в `localStorage`;
- продуктовый локальный режим: Node.js сервер сохраняет ответы в файл, отчет формируется локальной rule-based логикой.

## Как запустить

### Статический режим

Откройте файл `index.html` в браузере.

### Локальный режим

1. Установите Node.js 18+.
2. Создайте файл `.env` рядом с `.env.example`.
3. При необходимости укажите порт:

```text
PORT=3000
TELEGRAM_BOT_TOKEN=
TELEGRAM_BOT_USERNAME=
BOT_API_BASE=http://localhost:3000
```

4. Запустите:

```powershell
npm run dev
```

5. Откройте:

```text
http://localhost:3000
```

## Запуск Telegram-бота

1. Создайте бота через BotFather.
2. Заполните в `.env`:

```text
TELEGRAM_BOT_TOKEN=token_from_botfather
TELEGRAM_BOT_USERNAME=your_bot_username
BOT_API_BASE=http://localhost:3000
```

3. В одном терминале запустите backend:

```powershell
npm run dev
```

4. Во втором терминале запустите бота:

```powershell
npm run bot
```

После этого в HRBP-интерфейсе у каждого запуска появится Telegram-ссылка вида `https://t.me/<bot>?start=<survey_id>`.

## Что уже работает

- прохождение опроса участником;
- сохранение ответов в `localStorage` браузера;
- загрузка тестовых ответов;
- сохранение ответов в `data/responses.local.json` при запуске через сервер;
- расчет средних оценок по блокам;
- определение зеленой / желтой / красной зоны;
- отображение дословных комментариев;
- генерация Markdown-отчета локальной логикой;
- Telegram-бот для прохождения опроса;
- копирование и скачивание отчета.

## Ограничения текущей версии

- AI-анализ через API временно отключен, чтобы не расходовать токены на раннем прототипе;
- Telegram-бот работает через long polling и хранит незавершенные сессии в памяти;
- нет общей базы;
- нет авторизации и ролей.

## Следующий технический шаг

Сделать продуктовый сценарий запуска опроса:

1. создать сущность `Survey`;
2. разделить ссылки для участника и HRBP;
3. добавить список запусков опроса;
4. хранить отчеты и action items по конкретному запуску.
5. после стабилизации бот-сценария подключить AI-анализ отдельным флагом.
